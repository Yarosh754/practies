## Роль и задача
Ты выступаешь в роли Senior FullStack-разработчика. Твоя задача — перевести React-приложение с использования локального состояния (localStorage) на взаимодействие с реальным REST API (NestJS), который находится в папке backend.

## Жесткие ограничения
1. НЕ РЕДАКТИРУЙ файл `src/frontend/src/api/schema.d.ts`. Этот файл генерируется автоматически из `openapi.yaml`.
2. НЕ РЕДАКТИРУЙ код бэкенда в папке `src/backend`. Работай только с фронтендом.
3. НЕ ИСПОЛЬЗУЙ нативный `fetch` или `axios`. Все запросы должны идти строго через типизированный клиент `apiClient` из файла `src/frontend/src/api/client.ts`.
4. НЕ ИСПОЛЬЗУЙ инлайн-стили (`style={{...}}`). Для всех стилей создавай классы в соответствующих `.css` файлах.

## Архитектура и API
1. Все данные (Объявления, Чаты, Уведомления, Избранное и так далее) теперь приходят с бэкенда.
2. Для авторизации используется Keycloak. Токен хранится в объекте `keycloak` из `useAuth()`.
3. Каждый запрос к API (кроме публичных, например, получения списка объявлений) должен содержать заголовок авторизации: `Authorization: Bearer <token>`.
4. Пример правильного запроса с токеном:
   `apiClient.GET('/notifications', { headers: { Authorization: 'Bearer ' + keycloak.token } })`

## Работа с изображениями
1. Бэкенд возвращает изображения в виде массива ID (например, `["uuid-1", "uuid-2"]`).
2. Теперь изображения не хранятся в localStorage. Компонент `ImageComponent` должен быть переписан так, чтобы формировать URL к бэкенду по ID.
3. Формат URL для получения картинки: `http://localhost:9100/images/{id}`.

## Типы данных
1. Не создавай новые интерфейсы в `types.ts`. Импортируй типы напрямую из сгенерированной схемы:
   `import type { components } from '../api/schema';`
   `type Ad = components['schemas']['Ad'];`
