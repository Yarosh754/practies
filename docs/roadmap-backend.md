# Личность пользователя хранится как логин

`author_id` объявления, избранное, уведомления и `sender_id` сообщения хранят `preferred_username`. Контракт берёт автора из токена и записывает логин.

После переименования логина в Keycloak объявления, чаты, избранное и уведомления остаются на старом имени. Новый вход их не видит. `sub` при этом не меняется.

# Чат задаётся строкой с клиента

`chatId` имеет вид `{id объявления}_{логин}_{логин}`. Сервер разбирает его выражением из двух кусков без символа `_`. Список чатов ищет участника через `split_part` по тому же символу.

Логин с `_` не разбирается, отправить сообщение нельзя. Два клиента, которые соберут логины в разном порядке, получат два чата на тех же людей и то же объявление. Сервер порядок не выравнивает. Отдельной строки чата нет, есть только сообщения с готовым `chat_id`.

# Список чатов читает всю переписку

`GET /chats` забирает все сообщения пользователя, группирует их в памяти и по ним считает последнее сообщение и число непрочитанных.

Индекс по `chat_id` и `created_at` здесь не используется. Условие ищет участника разбором `chat_id` по символу `_`.

# Списки объявлений без страниц

`GET /ads` возвращает все строки под фильтр. Это каталог, объявления автора и выборка модератора по статусу. Курсора и `limit` нет.

# Статус объявления записывается без переходов

Автор может поставить `SOLD` или `DELETE` из любого текущего статуса, включая модерацию и отказ. Админ через `PATCH /ads/{id}/status` может записать любой статус и обойти отдельную модерацию.

Условной записи «только если статус ещё прежний» нет. Два запроса читают одно состояние и по очереди его затирают.

Категория и город при создании объявления принимаются как любые непустые строки. `/dictionaries` отдаёт фиксированный список, сервис объявлений с ним не сверяется.

# Прочтение происходит внутри загрузки сообщений

`GET /chats/{chatId}/messages` сначала помечает чужие сообщения прочитанными, потом возвращает ленту. Повторное открытие, второе устройство и обновление списка чатов из-за этого расходятся. Счётчик непрочитанных меняет запрос, который снаружи выглядит как чтение.
